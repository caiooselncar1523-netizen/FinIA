# ADR-0002: PostgreSQL como banco de dados principal

**Status:** Aceito
**Data:** 2026-09-17

## Contexto

O FinIA lida com dados essencialmente relacionais e que exigem integridade forte: transações financeiras, orçamentos, ativos de carteira — tudo isso tem relacionamentos claros entre entidades (usuário → conta → transação → categoria) e precisa de consistência (ex: um valor de transação não pode "sumir" por uma falha de escrita).

## Decisão

Usar **PostgreSQL** como banco de dados principal, com **Redis** como camada de cache para dados de leitura frequente e de baixa mutabilidade no curto prazo (cotações de ativos).

## Alternativas consideradas

- **MongoDB (NoSQL)** — mais flexível para dados não estruturados, mas dados financeiros se beneficiam mais de schema rígido, transações ACID e relacionamentos bem definidos. Descartado.
- **MySQL** — equivalente em muitos aspectos, mas PostgreSQL tem suporte nativo mais robusto a tipos de dados avançados (JSON, arrays) e é o padrão de fato em boa parte do mercado atual, o que também favorece o objetivo de portfólio.
- **Só PostgreSQL, sem cache** — descartado porque cotações de ativos são consultadas com frequência e a API externa (Brapi.dev) tem limite de requisições no plano gratuito; cache evita estourar esse limite.

## Consequências

- Necessário manter uma estratégia clara de invalidação de cache no Redis (ex: cotações expiram em X minutos).
- Todo o modelo de dados deve ser desenhado com chaves estrangeiras e constraints bem definidas desde o início (ver modelagem em `docs/database/`).
